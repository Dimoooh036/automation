# Лабораторная работа №2 (IW02) — Python-скрипт для работы с Web API

Скрипт `currency_exchange_rate.py` получает **курс валюты по отношению к другой
на заданную дату** через API сервиса курсов валют и сохраняет ответ в JSON-файл
в каталоге `data` в корне проекта. Ошибки обращения к API выводятся в консоль
и записываются в журнал `error.log` в корне проекта.

```
automation/                      <- корень проекта
├── lab02/
│   ├── currency_exchange_rate.py  <- скрипт
│   ├── requirements.txt           <- зависимости
│   └── readme.md                  <- этот файл
├── data/                          <- результаты запросов (создаётся автоматически)
│   └── USD_EUR_2025-03-17.json
└── error.log                      <- журнал ошибок (создаётся автоматически)
```

---

## 1. Подготовка: запуск сервиса

Скрипт работает с сервисом из проекта-поддержки (`lab02prep`, приложение на
PHP + Apache). Данные сервиса — курсы валют за период **2025-01-01 — 2025-09-15**,
базовая валюта `MDL`, доступны `USD`, `EUR`, `RON`, `RUS`, `UAH`.

```bash
cd lab02prep
cp sample.env .env        # в .env задаётся API_KEY
docker compose up -d      # сервис поднимется на http://localhost:8080
```

Проверить, что сервис отвечает:

```bash
curl "http://localhost:8080/?currencies" -X POST -d "key=EXAMPLE_API_KEY"
# {"error":"","data":["MDL","USD","EUR","RON","RUS","UAH"]}
```

## 2. Установка зависимостей

Нужен Python 3.9+ и единственная внешняя библиотека — `requests`.

```bash
cd lab02
python -m pip install -r requirements.txt
```

Или одной командой (в таком случае запускать скрипт нужно из каталога `lab02`):

```bash
python -m pip install "requests>=2.31,<3"
```

## 3. Запуск скрипта

Формат команды:

```
python currency_exchange_rate.py <валюта> <валюта> <YYYY-MM-DD> [ключи]
```

| Пример | Что делает |
| --- | --- |
| `python currency_exchange_rate.py USD EUR 2025-03-17` | Курс USD → EUR на 17.03.2025 |
| `python currency_exchange_rate.py usd eur 2025-03-17` | То же самое: регистр не важен, скрипт приводит код к верхнему |
| `python currency_exchange_rate.py EUR MDL 2025-09-15` | Курс EUR → MDL на последнюю дату данных |
| `python currency_exchange_rate.py RON UAH 2025-05-07` | Курс RON → UAH |
| `python currency_exchange_rate.py USD EUR 2025-01-01 --verbose` | Подробный журнал всех событий в `error.log` |
| `python currency_exchange_rate.py --list-currencies` | Список валют, поддерживаемых сервисом |
| `python currency_exchange_rate.py USD EUR 2025-03-17 --api-key MY_KEY` | Свой ключ API |
| `python currency_exchange_rate.py USD EUR 2025-03-17 --api-url http://127.0.0.1:8080/` | Другой адрес сервиса |

Ключи запуска:

| Ключ | Назначение |
| --- | --- |
| `-u`, `--api-url` | Адрес сервиса, по умолчанию `http://localhost:8080/` |
| `-k`, `--api-key` | Ключ API; по умолчанию берётся из переменной окружения `API_KEY` (иначе `EXAMPLE_API_KEY`) |
| `--timeout` | Таймаут запроса в секундах, по умолчанию `10` |
| `--retries` | Число попыток при сетевых сбоях, по умолчанию `3` |
| `--allow-any-date` | Разрешить даты вне периода данных 2025-01-01 — 2025-09-15 |
| `-v`, `--verbose` | Писать в `error.log` не только ошибки, но и все события |
| `--list-currencies` | Показать список валют сервиса и выйти |

## 4. Как устроен скрипт

Логика работы: **разбор аргументов → проверка входных данных → HTTP-запрос →
разбор и проверка ответа API → сохранение JSON → вывод отчёта**. Ошибки на
любом этапе превращаются в понятное сообщение в консоли и запись в `error.log`.

### Модули и структура

| Блок | Назначение |
| --- | --- |
| Константы | Адрес и ключ API по умолчанию, таймаут, число попыток, шаблоны проверки валюты и даты, период данных |
| Исключения | `CurrencyExchangeError` и наследники: `ValidationError`, `ApiError`, `NetworkError`, `StorageError` |
| Пути и журналирование | `find_project_root()`, `setup_console()`, `setup_logging()` |
| Аргументы | `parse_args()`, `validate_connection()`, `validate_request_args()`, `validate_currency()`, `validate_date()` |
| Работа с API | `ApiConfig`, `_request()`, `_parse_response()`, `fetch_rate()`, `fetch_currencies()` |
| Сохранение | `build_filename()`, `save_result()` |
| Точка входа | `run_list_currencies()`, `run_rate_request()`, `main()` |

### Основные функции

- **`find_project_root()`** — определяет корень проекта: поднимается от каталога
  скрипта вверх, пока не найдёт `.git` или `README.md`. Благодаря этому `data/`
  и `error.log` создаются именно в корне проекта, а не рядом со скриптом.

- **`setup_console()`** — переводит вывод консоли в UTF-8. На Windows консоль по
  умолчанию работает в однобайтовой кодировке (cp1251/cp866), где нет символа
  «→», и вывод падал бы с `UnicodeEncodeError`.

- **`setup_logging()`** — настраивает журналирование: ошибки и предупреждения
  идут и в консоль, и в `error.log` в корне проекта; остальные сообщения — только
  в консоль (с ключом `--verbose` — также в файл). Формат строки файла:
  `дата и время | уровень | сообщение`.

- **`parse_args()`** — `argparse`: три позиционных аргумента (валюта, валюта,
  дата) и дополнительные ключи; заодно реализована справка `--help`.

- **`validate_connection()`** — проверяет параметры подключения (адрес API с
  префиксом `http(s)://`, непустой ключ, положительный таймаут и число попыток)
  до любого сетевого запроса и возвращает готовый `ApiConfig`.

- **`validate_request_args()`** — проверяет коды валют и дату, возвращает
  нормализованный набор `(base, quote, date)`.

- **`validate_currency()`** — проверяет, что код состоит из трёх букв, и
  приводит его к верхнему регистру: сервис принимает только заглавные буквы
  (`usd` приведёт к ошибке «The currency is unknown»).

- **`validate_date()`** — проверяет формат `YYYY-MM-DD` (с подсказкой, если введено
  `17-03-2025`), существование даты (отсекает `2025-02-30`) и принадлежность
  периоду данных 2025-01-01 — 2025-09-15.

- **`_request()`** — выполняет HTTP-запрос: GET-параметры `from`/`to`/`date`
  в адресе, ключ `key` — в теле POST (так требует сервис). Сетевые ошибки
  (таймаут, отказ в соединении) повторяются до `--retries` раз с нарастающей
  паузой 1 с, 2 с, 3 с.

- **`_parse_response()`** — приводит ответ к общему виду и проверяет его:
  * неуспешный HTTP-код → ошибка с кодом и сокращённым телом ответа;
  * ответ не является JSON (сервис отдаёт HTML при неверной дате) → понятное
    сообщение вместо падения;
  * **непустое поле `error`** — главный признак ошибки в этом API: сервис
    всегда отвечает кодом 200, поэтому HTTP-код не позволяет определить ошибку;
  * отсутствие поля `data` или `rate` → ошибка формата ответа.

- **`save_result()`** — создаёт каталог `data` (если его нет) и записывает JSON
  с метаданными запроса и ответом. Файл сначала пишется во временный
  `*.json.tmp` и только потом переименовывается, поэтому прерванный запуск не
  оставит повреждённый JSON.

- **`main()`** — связывает всё вместе, перехватывает ожидаемые ошибки,
  возвращает код возврата и закрывает сессию `requests` через `with`.

### Особенности API, которые учтены в скрипте

1. **Ошибки возвращаются с HTTP 200** — признак ошибки только непустое поле
   `error` в теле ответа.
2. **Коды валют — только в верхнем регистре** — ввод `usd` нормализуется в `USD`.
3. **Дата строго `YYYY-MM-DD`** — иначе сервис падает с HTML-ошибкой PHP, поэтому
   дата проверяется до отправки запроса.
4. **Даты вне периода данных** сервис не отвергает, а молча подставляет последний
   известный курс, возвращая запрошенную дату. Скрипт такие даты отклоняет
   (обход — `--allow-any-date`), а если дата в ответе не совпала с запрошенной,
   пишет предупреждение в журнал.
5. **Валюта `RUS` указана в списке, но не работает** — в данных сервиса поле
   называется `rub`, поэтому запрос `USD → RUS` возвращает ошибку
   `Unknown currency rus`. Скрипт корректно показывает эту ошибку.

### Обработка ошибок

| Ситуация | Поведение скрипта |
| --- | --- |
| Неверный ключ API | Сообщение сервиса `Invalid API key` в консоль и `error.log`, код возврата 1 |
| Неизвестная валюта | Сообщение `The currency XXX is unknown`, код возврата 1 |
| Неверный формат даты | Отказ **до** запроса с подсказкой про `YYYY-MM-DD`, код возврата 2 |
| Несуществующая дата (`2025-02-30`) | Отказ до запроса, код возврата 2 |
| Дата вне периода данных | Отказ с пояснением, код возврата 2 (обход — `--allow-any-date`) |
| Одинаковые валюты | Отказ с пояснением, код возврата 2 |
| Некорректный код валюты (`ua`) | Отказ с пояснением, код возврата 2 |
| Сервис не запущен | 3 попытки, затем сообщение «проверьте, что сервис запущен (docker compose up -d)», код возврата 1 |
| Ответ не является JSON | Сообщение со сокращённым телом ответа вместо падения, код возврата 1 |
| Не переданы обязательные аргументы | Подсказка по запуску, код возврата 2 |

Коды возврата: `0` — успех, `1` — ошибка API/сети/файла, `2` — некорректные аргументы.
